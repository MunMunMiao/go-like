# go-like 0.0.1 首发说明

状态：首发候选基线，尚未以本仓库证据证明 npm 发布完成。

go-like 0.0.1 是面向后端 TypeScript 的 Go 风格微服务工具包首个公共版本。所有公共包都从
`0.0.1` 起步；运行时只依赖标准 Web API，Node.js、Bun 与 Deno 的专有能力由显式子路径或适配包承接。

## 首发版本规则

首发实现期间产生的变更记录已原样归档到
[`docs/releases/0.0.1/changesets`](./0.0.1/changesets/)，不再放在 `.changeset` 活动目录中。它们记录的
是 0.0.1 已包含的实现，不是 0.0.1 之后待发布的变更；重复消费会错误地把首发版本提升为
`0.1.0` 或 `0.0.2`。

首次发布前不要运行 `bun run version:packages`。当前 42 个公共包尚未在 npm 建立，无法预先配置 trusted publisher，
因此纯 OIDC 不能创建 0.0.1 包。首次发布按以下一次性流程执行：

1. 先保护 `main`，限制直接推送并把 `Verify / Verify` 设为 required check；创建仅允许 `main` 的 `npm`
   environment。存在第二位维护者时，再启用 required reviewer 和 prevent self-review。
2. scope owner 创建有效期 1 天、仅限 `@go-like` scope read/write 的 granular token，并临时保存为该 environment 的
   `NPM_BOOTSTRAP_TOKEN`。
3. 从 `main` 手动运行 `release.yml` 并启用 `bootstrap`。workflow 会对同一 SHA 重跑格式、类型、构建、单元测试、
   audit、文档构建、runtime consumer 与 published tarball 门禁，再发布缺失的 0.0.1 包并生成 provenance。
4. 成功后立即删除 environment secret、撤销 token 并回读。随后通过 npm 网站或 `npm trust github` 为全部公共包配置
   `MunMunMiao/go-like`、`release.yml`、`npm` environment 和 `npm publish` 权限，再禁止传统 token 发布。
5. 后续版本保持 `bootstrap=false`，只允许 GitHub-hosted runner 使用 OIDC trusted publishing。

bootstrap 只接受 `@go-like/*@0.0.1`。部分发布失败后可用同一 SHA 重跑，Changesets 会跳过已经存在的精确版本；npm
仍负责拒绝无权限、版本冲突和 registry 错误。

若 npm 发布成功但 tag push 失败，不得修改版本或重复 bump。应从原 SHA 以同一模式重跑：Changesets 会跳过 registry
中已经存在的精确版本，`changeset tag` 补齐本地 tags，再执行 `git push origin --follow-tags`。首次发布之后恢复标准
Changesets 流程：新增 Changeset、应用版本、审查版本与锁文件，再执行发布入口。

## 核心能力

- Go 风格 `Context`、应用生命周期、结构化 Server、Health 与优雅停止；Core 提供 startup admission 与完整
  shutdown pipeline 的单一绝对 deadline，并让 Node 第二次终止信号恢复默认强退。
- 内部微服务 Client、Registry、Selector、Transport、HTTP/Memory transport。
- Client idle owner 在全局 size 与 TTL 边界内复用，默认为 100 个与 60,000ms。
- 外部 Web Fetch 接口；Hono、Elysia 与 H3 直接使用各自原生 Fetch 入口。
- Config、Store、Broker、Cache 与面向 Consul、etcd、Kubernetes、Vault、Redis、RabbitMQ 等组件的实现。
- RabbitMQ stable subscriber 会在恢复期间合并重复 `basic.cancel` 通知，在当前恢复后继续重建 consumer，
  接收 replacement consumer 注册期间立即到达的 delivery，并忽略旧 generation 迟到的取消通知。
- Config 可在成功 load 后通过一次性 terminal callback 立即撤销 readiness，同时保留 last-good 与真实 owner drain。
- Consul、etcd、ZooKeeper 与 mDNS Registry 可通过一次性 registration terminal callback 观察后台注册永久失效，
  且不改变 Registrar/Registry SPI。
- Croner、BullMQ、NATS/JetStream、OpenTelemetry、Prometheus、Pino 与 Winston 适配。
- Bun workspace 构建与单元测试，以及本地执行的发布包、跨运行时和真实 Docker E2E。
- 独立的本地 60 分钟 soak 命令用于观察 Fetch HTTP、Client pool、停机和资源趋势；它不属于 hosted CI 或发布门禁。

Core timeout 是 caller wait boundary，不是任意 Promise 或原生资源已经 terminal 的证明。迟到结果仍被观察，
必要 cleanup 仍会被调用；原生 graceful-to-force 由具体 Server adapter 负责，Core 不调用 `process.exit()`。

## 明确边界

0.0.1 不提供 gRPC、Proto/IDL、Event Store、历史查询或事件 replay，也不扩展当前 Registry provider
集合。这些边界是项目决策，不属于首发遗漏。

仓库内门禁完成仍不等于 production-proven。推送并保护 `main`、创建受保护 `npm` environment、启用 private
vulnerability reporting 与 Dependabot security updates、完成 npm bootstrap/trusted publisher、运行 hosted CI、
通过一次本地 60 分钟 soak 和真实 production pilot，均属于发布前必须取得的外部证据。
