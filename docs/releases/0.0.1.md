# go-like 0.0.1 首发说明

状态：首发候选基线，尚未以本仓库证据证明 npm 发布完成。

go-like 0.0.1 是面向后端 TypeScript 的 Go 风格微服务工具包首个公共版本。所有公共包都从
`0.0.1` 起步；运行时只依赖标准 Web API，Node.js、Bun 与 Deno 的专有能力由显式子路径或适配包承接。

## 首发状态

首发实现期间产生的变更说明原样保存在 [`docs/releases/0.0.1/changesets`](./0.0.1/changesets/)，仅作为 `0.0.1`
已包含内容的历史证据，不是任何工具的活动输入。

仓库当前不提供自动版本或 npm 发布流程，本文件也不授权发布。首次公开发布前必须通过独立变更确定版本策略、凭据边界、
首次建包、部分失败恢复和 tag 规则，并对实际发布路径重新验证。

## 核心能力

- Go 风格 `Context`、应用生命周期、结构化 Server、Health 与优雅停止；Core 提供 startup admission 与完整
  shutdown pipeline 的单一绝对 deadline，并让 Node 第二次终止信号恢复默认强退。
- 内部微服务 Client、Registry、Selector、Transport、HTTP/Memory transport。
- Client idle owner 在全局 size 与 TTL 边界内复用，默认为 100 个与 60,000ms。
- 外部 Web Fetch 接口；Hono、Elysia 与 H3 直接使用各自原生 Fetch 入口。
- Config、Store、Broker、Cache 与面向 Consul、etcd、Kubernetes、Vault、Redis、RabbitMQ 等组件的实现。
- RabbitMQ stable subscriber 会在恢复期间合并重复 `basic.cancel` 通知，在当前恢复后继续重建 consumer，
  接收 replacement consumer 注册期间立即到达的 delivery，并忽略旧 generation 迟到的取消通知。
- Config 可在成功 load 后通过一次性 terminal callback 立即撤销 readiness，同时保留 last-good 与真实 owner drain。
- Consul、etcd、ZooKeeper 与 mDNS Registry 可通过一次性 registration terminal callback 观察后台注册永久失效，
  且不改变 Registrar/Registry SPI。
- Croner、BullMQ、NATS/JetStream、OpenTelemetry、Prometheus、Pino 与 Winston 适配。
- Bun workspace 构建与单元测试，以及本地执行的发布包、跨运行时和真实 Docker E2E。
- 独立的本地 60 分钟 soak 命令用于观察 Fetch HTTP、Client pool、停机和资源趋势；它不属于 hosted CI 或发布门禁。

Core timeout 是 caller wait boundary，不是任意 Promise 或原生资源已经 terminal 的证明。迟到结果仍被观察，
必要 cleanup 仍会被调用；原生 graceful-to-force 由具体 Server adapter 负责，Core 不调用 `process.exit()`。

## 明确边界

0.0.1 不提供 gRPC、Proto/IDL、Event Store、历史查询或事件 replay，也不扩展当前 Registry provider
集合。这些边界是项目决策，不属于首发遗漏。

仓库内门禁完成仍不等于 production-proven。推送并保护 `main`、确定并验证实际 npm 发布流程、启用 private
vulnerability reporting 与 Dependabot security updates、运行 hosted CI、通过一次本地 60 分钟 soak 和真实
production pilot，均属于发布前必须取得的外部证据。
