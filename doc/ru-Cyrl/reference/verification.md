# Проверка

Команда может существовать и при этом не пройти. Один зелёный lane не означает, что работает каждый plug, runtime, пример или упакованный tarball. Запишите дерево-кандидат, версии инструментов, точную команду, код выхода, счётчики и очистку.

## Lane доказательств

| Lane                | Что проверяет                                                                           | Внешние сервисы          | Чего успешный проход не доказывает            |
| ------------------- | --------------------------------------------------------------------------------------- | ------------------------ | --------------------------------------------- |
| Формат              | Форматирование исходников и документации                                                | Нет                      | Поведение runtime                             |
| Lint                | Правила Oxlint                                                                          | Нет                      | Типы или поведение runtime                    |
| Проверка типов      | TypeScript корня, пакетов, примеров и E2E                                               | Нет                      | Выход сборки или поведение провайдера         |
| Модульные тесты     | Детерминированные тесты                                                                 | Нет                      | Реальную сеть, Docker или упакованные tarball |
| Сборка              | ESM пакетов и объявления                                                                | Нет                      | Разрешение у потребителя                      |
| Runtime E2E         | Фикстуры Bun и Node там, где они объявлены                                              | Обычно нет               | Каждый plug                                   |
| E2E провайдеров     | Consul, etcd, Kubernetes, ZooKeeper, Redis, RabbitMQ, NATS и другие объявленные сервисы | Да                       | Доступность в production или размещённый CI   |
| E2E примеров        | Процесс примера, запрос, readiness, остановку и очистку                                 | Иногда                   | Отдельную установку каждого примера           |
| Опубликованное      | Упакованные tarball, которые потребляют фикстуры Node и Bun                             | Нет, кроме импортов plug | Публикацию в npm                              |
| Soak                | Долгое поведение HTTP или сервиса                                                       | Обычно нет               | Короткий тест или каждый plug                 |
| Сборка документации | VitePress                                                                               | Нет                      | Раскладку в браузере или качество перевода    |
| Аудит               | Отчёт об уязвимостях зависимостей                                                       | Нет                      | Авторизацию приложения                        |

Текущий публичный инвентарь — 20 пакетов и 75 точек входа. См. [Пакеты](/ru-Cyrl/reference/packages).

## Объявленные команды

Из корня репозитория:

```sh
bun install --frozen-lockfile
bun run verify
```

`bun run verify` выполняет `test:protobuf`, `fmt:check`, `lint:check`, `typecheck`, `build` и `test:unit:coverage` в этом порядке. Стадия покрытия запускает каждый скрипт покрытия корня и workspace и заканчивается `coverage:verify`. `examples/payments-ledger` — исключение области модульных тестов: его скрипт покрытия также запускает сценарий PostgreSQL и NATS и поэтому нуждается в Docker.

`fmt` исправляет форматирование. `lint` применяет безопасные исправления Oxlint, форматирует результат и завершается успешно только при нуле предупреждений:

```sh
bun run fmt
bun run lint
```

Отдельные стадии сужают сбой. Проход одной стадии не заменяет `verify`:

```sh
bun run test:protobuf
bun run fmt:check
bun run lint:check
bun run typecheck
bun run build
bun run test:unit
bun run test:unit:coverage
bun run test:parallel
bun run test:stability
```

`test:unit:coverage` проверяет инвентарь исполняемых исходников и покрытие строк и функций по файлам. Покрытие ветвей оно не заявляет. `test:stability` перемешивает каждый запуск корня и workspace, повторяет каждый файл тестов дважды и печатает seed. Повтора при сбое нет. `test:parallel` один раз запускает область модульных тестов двумя изолированными worker Bun. Ни stability, ни parallel не входят в `verify`.

Сборка документации и аудит остаются отдельными:

```sh
bun run doc:build
bun run audit
```

`test:protobuf` запускает Buf lint и генерацию, проверяет типы сгенерированных фикстур и выполняет свой интеграционный тест RPC. Это не проверка формата только на чтение.

## Области E2E

Корневые скрипты:

```sh
bun run test:e2e:suites
bun run test:e2e:runtimes
bun run test:e2e:providers
bun run test:e2e:examples
bun run test:e2e:published
bun run test:e2e
bun run test:e2e:soak
bun run test:e2e:grpc-soak
```

Скрипты областей сначала собирают проект, кроме `test:e2e:grpc-soak`, который генерирует protobuf и затем запускает `e2e/grpc-soak.ts`. Прямой `bun e2e/run.ts --scope <name>` не обязательно собирает. Назовите, какой именно запуск вы выполнили.

E2E провайдеров нуждается в объявленных сервисах Docker и очистке. Проверки опубликованного упаковывают tarball и устанавливают их в подготовленных потребителей. Soak по умолчанию длится 60 минут:

```sh
bun run test:e2e:soak
```

Короткий прогон HTTP — не этот soak.

Эта страница перечисляет скрипты корневого манифеста. Код выхода для них она не записывает. Пошаговая раскладка наборов живёт рядом с E2E-runner, а не здесь.

## Наблюдение инструментария

Репозиторий не объявляет версии runtime или инструментов как требования к выполнению. Lane проверяет, что каждый нужный инструмент может выполниться, и затем записывает окружение. Отсутствующий инструмент, timeout, ненулевой статус или падающий потребитель проваливают запуск. Строка версии этого не делает.

Версии зависимостей, lockfile и фиксированные фикстуры — входы воспроизводимости.

## Базовые доказательства этого трека документации

Поставленный аудит контракта сообщил следующее на commit `9385dbf5b6a7d913be56a80ade359e1bf9be8675`:

```text
bun run typecheck  -> passed
bun run test:unit  -> passed, 2,736 tests across root and 87 workspaces
bun run fmt:check  -> passed, 1,514 files
source export audit -> 66 declared entries imported without an import error
```

Этот аудит описывает дерево до миграции. Текущие исходники экспортируют 75 точек входа в 20 пакетах. Аудит не запускал `build`, `doc:build`, `audit`, Docker E2E провайдеров, выполнение на разных runtime, проверки опубликованных tarball, запросы npm, размещённый CI и 60-минутный soak. Эта правка документации не заменяет ту запись новым успешным результатом.

## Что позволяет сказать результат

| Результат                  | Безопасная формулировка                                                     |
| -------------------------- | --------------------------------------------------------------------------- |
| Осмотр экспорта исходников | «Пакет экспортирует этот символ на этом дереве.»                            |
| Узкая проверка типов       | «Эти исходники проходят проверку типов под этой командой.»                  |
| Узкий модульный тест       | «Эти случаи прошли под этой командой.»                                      |
| `bun run verify`           | «Записанная последовательность verify прошла для этого дерева и окружения.» |
| E2E провайдера             | «Этот сценарий прошёл с записанным сервисом и очисткой.»                    |
| Фикстура runtime           | «Эта фикстура прошла под этой версией runtime.»                             |
| Опубликованный потребитель | «Этот упакованный артефакт потребила записанная фикстура.»                  |
| Сборка документации        | «VitePress собрал настроенные маршруты.»                                    |
| Soak                       | «Эта длительность и нагрузка завершились с записанными остатками.»          |

Для редакционного журнала используйте [Утверждения](/reference/claims).

## Известные границы

- `publishConfig` в манифесте не устанавливает публикацию в npm.
- Файл workflow не устанавливает результат размещённого CI.
- Скрипт пакета может быть объявленным lane без недавнего прохода.
- Провайдеры в памяти не устанавливают межпроцессное поведение или поведение протокола поставщика.
- Web `ReadableStream` не устанавливает внутренний полнодуплексный RPC.
- Параметры TLS не устанавливают аутентификацию приложения.
- Timeout остановки не устанавливает, что каждый нативный ресурс закончился.
