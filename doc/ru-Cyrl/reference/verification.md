# Проверка

Зелёный unit test — конкретное свидетельство, а не универсальная гарантия. Переносимые пакеты проходят строгий TypeScript, source policy, coverage production-кода, build и smoke опубликованного пакета. Где этого требует контракт, отдельные runtime lanes проверяют Bun, Node.js и Deno.

Внешние провайдеры тестируются с настоящими контейнерами, закреплёнными неизменяемым digest. Наборы создают реальные ресурсы Consul, etcd, NATS, OpenTelemetry Collector, Redis/BullMQ, ZooKeeper и Kubernetes/K3s, проверяют поведение и затем очистку. Fake полезен для детерминированных границ, но не заменяет реальную protocol gate.

Единственная полная корневая gate, блокирующая выпуск:

```sh
bun run verify
```

Docker-команды провайдера и более узкие проверки хранятся в его `package.json` и выводят машиночитаемый маркер результата. Они полезны для диагностики, но не заменяют полную корневую gate. Статус выпуска определяет только terminal result последнего полного запуска `bun run verify`; также проверяются сгенерированное содержимое, workspace manifests, удаление Docker-ресурсов и `git status`. Сам факт запуска команды или тихий лог ещё не означает успех.
