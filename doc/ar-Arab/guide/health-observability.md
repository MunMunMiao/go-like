# الصحة وقابلية الرصد

يفصل `@likego/health` بين liveness وreadiness. يكون سجل liveness الفارغ سليماً لأن العملية نفسها تعمل، بينما يفشل سجل readiness الفارغ بحالة مغلقة: لا ينبغي توجيه الحركة إلى الخدمة قبل تسجيل فحص جاهزية واحد على الأقل ونجاح جميع الفحوص المسجلة. ويمكن لمعالج `@likego/web/health` الاختياري عرض هذه النتائج في استجابات Web قياسية.

المقاييس والتتبّع صريحان أيضاً. تعرض `@likego/prometheus` سجل `prom-client` يملكه التطبيق ولا تلمس السجل العام. وتقبل `@likego/otel` مزوّدات OpenTelemetry يملكها التطبيق لربطها بدورة الحياة، كما توفر أغلفة واضحة لعميل LikeGo وunary middleware والوسيط. لا تثبّت الحزمة مزوّدات عامة أو exporters أو context managers أو automatic instrumentation.

تتبع محوّلات التدوين القاعدة نفسها. تقبل `@likego/pino` و`@likego/winston` الوجهات أو loggers الأصلية، ولا تديران سوى حد الإيقاف. تبقى المستويات وسياسة redaction والتنسيقات وtransports وchild loggers وسياسة الحقول ضمن شيفرة التطبيق.

اضبط عدد القيم الممكنة للوسوم، ولا تضع بيانات اعتماد داخل attributes، وثبّت context manager تدعمه بيئة التشغيل قبل توقع انتقال علاقة الأبوة في trace عبر العمل غير المتزامن. وإذا فشل تصدير telemetry، فيجب أن تسجل دورة الحياة هذا الفشل بدلاً من إعلان إيقاف نظيف على نحو مضلل.
