# التدفق

يعتمد LikeGo نموذج التدفق الموجود أصلاً في منصة Web. فالطلب المتدفق هو `Request` قياسي، والاستجابة المتدفقة هي `Response` قياسية قد يحمل جسمها `ReadableStream<Uint8Array>`. لا يضيف المشروع فئة تدفق خاصة، ولا DSL للإطارات، ولا قناة ثنائية الاتجاه وهمية فوق هذه الواجهات.

ينتمي تدفق HTTP العام إلى `@likego/web` وإلى Handler الأصلي لإطار العمل. أما `@likego/client` و`@likego/transport` الداخليان فيقدمان حالياً استدعاءات `Message` أحادية فقط، ولا ينشران Fetch Transport أو Stream Client منفصلين.

هذا الفصل مهم لأن أجسام Web تُقرأ مرة واحدة. ينبغي للـ middleware ألا يقرأ الجسم إلا إذا كان سيوفر بديلاً عنه، ويجب أن ينتقل الإلغاء عبر إشارة الطلب وعبر `Context` الموجود في أول المعاملات. تتحقق طبقة النقل أيضاً من أن مقاطع التدفق هي `Uint8Array`؛ فإذا وصل مقطع غير صالح أصبح ذلك خطأ بروتوكول واضحاً، لا بيانات فارغة بصمت.

استخدم `@likego/web` مع محوّل إطارك المفضل لنقاط HTTP العامة. تستطيع Hono وElysia وH3 إنشاء SSE أو استجابات متدفقة أو ترقيات WebSocket خاصة ببيئة التشغيل مباشرة. يحافظ LikeGo فقط على هوية `Request` و`Response` والتدفق والخطأ الأصلية، ولا يحاول إعادة تعريفها.
