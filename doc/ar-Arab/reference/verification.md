# التحقق

يمكن أن يوجد أمر من دون أن يكون قد نجح. مسار أخضر واحد لا يعني أن كل Plug أو بيئة تشغيل أو مثال أو tarball معبأ يعمل. سجّل شجرة المرشّح، وإصدارات الأدوات، والأمر الدقيق، وحالة الخروج، والأعداد، والتنظيف.

## مسارات الدليل

| المسار              | ما يفحصه                                                                          | خدمات خارجية          | ما لا يثبته النجاح                       |
| ------------------- | --------------------------------------------------------------------------------- | --------------------- | --------------------------------------- |
| Format              | تنسيق المصدر والتوثيق                                                             | لا                     | سلوك وقت التشغيل                        |
| Lint                | قواعد Oxlint                                                                      | لا                     | الأنواع أو سلوك وقت التشغيل              |
| Typecheck           | TypeScript للجذر والحزمة والمثال وE2E                                             | لا                     | مخرجات البناء أو سلوك المزوّد            |
| Unit                | اختبارات حتمية                                                                    | لا                     | شبكة حقيقية أو Docker أو tarballs معبأة |
| Build               | ESM للحزمة وإعلانات الأنواع                                                         | لا                     | حل المستهلك                             |
| Runtime E2E         | تجهيزات Bun وNode حيث أُعلنت                                                       | عادة لا                | كل Plug                                 |
| Provider E2E        | Consul وetcd وKubernetes وZooKeeper وRedis وRabbitMQ وNATS والخدمات المعلنة الأخرى | نعم                   | التوفر في الإنتاج أو hosted CI           |
| Example E2E         | عملية المثال والطلب والجاهزية والإيقاف والتنظيف                                    | أحياناً                | تثبيت منفصل لكل مثال                    |
| Published           | tarballs معبأة تستهلكها تجهيزات Node وBun                                         | لا، عدا استيرادات Plug | النشر على npm                           |
| Soak                | سلوك HTTP أو خدمة طويل المدة                                                      | عادة لا                | اختبار قصير، أو كل Plug                 |
| Documentation build | VitePress                                                                         | لا                     | تخطيط المتصفح أو جودة الترجمة           |
| Audit               | تقرير ثغرات الاعتماديات                                                            | لا                     | تفويض التطبيق                           |

الجرد العام الحالي 20 حزمة و75 مدخلاً. راجع [الحزم](/ar-Arab/reference/packages).

## الأوامر المعلنة

من جذر المستودع:

```sh
bun install --frozen-lockfile
bun run verify
```

يشغّل `bun run verify` بالترتيب `test:protobuf` و`fmt:check` و`lint:check` و`typecheck` و`build` و`test:unit:coverage`. تشغّل مرحلة التغطية كل script تغطية للجذر وworkspace وتنتهي بـ `coverage:verify`. `examples/payments-ledger` هو استثناء نطاق الوحدة الذي يشغّل script تغطيته أيضاً سيناريو PostgreSQL وNATS ولذلك يحتاج إلى Docker.

يصلح `fmt` التنسيق. يطبّق `lint` إصلاحات Oxlint الآمنة، وينسّق النتيجة، وينجح فقط مع صفر من التحذيرات:

```sh
bun run fmt
bun run lint
```

تضيّق المراحل المفردة الإخفاق. نجاح مرحلة واحدة لا يحل محل `verify`:

```sh
bun run test:protobuf
bun run fmt:check
bun run lint:check
bun run typecheck
bun run build
bun run test:unit
bun run test:unit:coverage
bun run test:parallel
bun run test:stability
```

يفحص `test:unit:coverage` جرد المصدر القابل للتنفيذ وتغطية الأسطر والدوال لكل ملف. وهو لا يدّعي تغطية الفروع. يرتّب `test:stability` كل تشغيل للجذر وworkspace عشوائياً، ويكرر كل ملف اختبار مرتين، ويطبع البذرة. وهو لا يعيد المحاولة. يشغّل `test:parallel` نطاق الوحدة مرة واحدة بعاملَي Bun معزولين. لا يدخل الاستقرار ولا التوازي في `verify`.

يبقى بناء التوثيق والتدقيق منفصلين:

```sh
bun run doc:build
bun run audit
```

يشغّل `test:protobuf` فحص Buf وتوليده، ويتحقق من أنواع التجهيز المولَّدة، ويشغّل اختبار تكامل RPC. وهو ليس فحص تنسيق للقراءة فقط.

## نطاقات E2E

scripts الجذر هي:

```sh
bun run test:e2e:suites
bun run test:e2e:runtimes
bun run test:e2e:providers
bun run test:e2e:examples
bun run test:e2e:published
bun run test:e2e
bun run test:e2e:soak
bun run test:e2e:grpc-soak
```

تبني scripts النطاق أولاً، عدا `test:e2e:grpc-soak`، الذي يولّد protobuf ثم يشغّل `e2e/grpc-soak.ts`. الأمر المباشر `bun e2e/run.ts --scope <name>` لا يبني بالضرورة. اذكر أيهما شغّلت.

يحتاج Provider E2E إلى خدمات Docker المعلنة وإلى التنظيف. تفحص فحوص النشر tarballs وتثبّتها في مستهلكين مُجهَّزين. الافتراضي لـ soak هو 60 دقيقة:

```sh
bun run test:e2e:soak
```

تشغيل HTTP قصير ليس ذلك الـ soak.

تسرد هذه الصفحة scripts الموجودة في manifest الجذر. وهي لا تسجّل حالة خروج لها. يعيش تخطيط الأطقم خطوة بخطوة مع مشغّل E2E، لا هنا.

## ملاحظة سلسلة الأدوات

لا يعلن المستودع إصدارات بيئة التشغيل أو الأدوات بوصفها متطلبات تنفيذ. يتحقق المسار من أن كل أداة مطلوبة تستطيع التنفيذ، ثم يسجّل البيئة. أداة غائبة، أو انتهاء مهلة، أو حالة غير صفرية، أو مستهلك فاشل يفشل التشغيل. وسلسلة الإصدار لا تفعل ذلك.

إصدارات الاعتماديات، وملف القفل، والتجهيزات الثابتة مدخلات لإعادة الإنتاج.

## دليل خط الأساس لمسار التوثيق هذا

أفاد تدقيق العقد المزوَّد بما يأتي على commit `9385dbf5b6a7d913be56a80ade359e1bf9be8675`:

```text
bun run typecheck  -> passed
bun run test:unit  -> passed, 2,736 tests across root and 87 workspaces
bun run fmt:check  -> passed, 1,514 files
source export audit -> 66 declared entries imported without an import error
```

يصف ذلك التدقيق شجرة ما قبل الترحيل. يصدّر المصدر الحالي 75 مدخلاً عبر 20 حزمة. ولم يشغّل التدقيق `build` أو `doc:build` أو `audit` أو E2E لمزوّدات Docker أو التنفيذ عبر بيئات التشغيل أو فحوص tarball المنشور أو استعلامات npm أو hosted CI أو soak لمدة 60 دقيقة. لا تستبدل مراجعة التوثيق هذه ذلك السجل بنتيجة نجاح جديدة.

## ما الذي تسمح به النتيجة

| النتيجة            | العبارة الآمنة                                      |
| ------------------ | -------------------------------------------------- |
| فحص تصدير المصدر   | «تصدّر الحزمة هذا الرمز عند هذه الشجرة.»            |
| فحص أنواع مركّز     | «تجتاز هذه المصادر فحص الأنواع تحت هذا الأمر.»       |
| اختبار وحدة مركّز   | «نجحت هذه الحالات تحت هذا الأمر.»                    |
| `bun run verify`   | «نجح تسلسل verify المسجّل لهذه الشجرة وهذه البيئة.» |
| Provider E2E       | «نجح هذا السيناريو مع الخدمة والتنظيف المسجّلين.»   |
| تجهيز بيئة التشغيل | «نجح هذا التجهيز تحت إصدار بيئة التشغيل هذا.»      |
| مستهلك منشور       | «استهلك التجهيز المسجّل هذا الأثر المعبأ.»           |
| بناء التوثيق       | «بنى VitePress المسارات المكوَّنة.»                  |
| Soak               | «اكتملت هذه المدة وهذا الحمل مع البقايا المسجّلة.»  |

استخدم [الادعاءات](/reference/claims) لدفتر التحرير.

## الحدود المعروفة

- لا يثبت `publishConfig` في manifest النشر على npm.
- لا يثبت ملف سير عمل نتيجة hosted CI.
- يمكن أن يكون script الحزمة مساراً معلناً بلا نجاح حديث.
- مزوّدات الذاكرة لا تثبت سلوكاً بين العمليات أو بروتوكول بائع.
- لا يثبت Web `ReadableStream` RPC داخلياً كامل الاتجاهين.
- خيارات TLS لا تثبت مصادقة التطبيق.
- مهلة الإيقاف لا تثبت أن كل مورد أصلي قد انتهى.
