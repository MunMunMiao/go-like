# التحقق

يعد LikeGo نجاح اختبار الوحدة نوعاً واحداً من الأدلة، لا برهاناً شاملاً لكل شيء. تمر الحزم القابلة للنقل بفحص TypeScript صارم، وفحص سياسة المصدر، وقياس تغطية الشيفرة الإنتاجية، والتحقق من البناء، واختبارات smoke للحزمة المنشورة. كما تختبر مسارات runtime بيئات Bun وNode.js وDeno المدعومة عندما ينطبق عليها عقد الحزمة.

تُختبر الأنظمة الخارجية داخل حاويات حقيقية، وتُثبّت صورة كل حاوية بواسطة image digest غير قابل للتغيير. تنشئ مجموعات الاختبار موارد فعلية في Consul وetcd وNATS وOpenTelemetry Collector وRedis/BullMQ وZooKeeper وKubernetes/K3s بحسب الحاجة، ثم تتحقق من السلوك ومن إزالة الموارد. يفيد المزوّد الوهمي في حالات الحواف الحتمية، لكنه لا يحل محل بوابة بروتوكول حقيقية.

بوابة الجذر الكاملة الوحيدة التي تمنع الإصدار هي:

```sh
bun run verify
```

توجد أوامر Docker الخاصة بكل مزوّد والفحوص الأضيق ضمن scripts الحزمة، وتنتج علامات نتائج قابلة لقراءة الآلة. تفيد هذه الأوامر في التشخيص، لكنها لا تستبدل بوابة الجذر الكاملة. لا تتحدد حالة الإصدار إلا بالنتيجة النهائية لآخر تشغيل كامل لـ `bun run verify`؛ ويجب أيضاً فحص محتويات الحزم المتولدة وworkspace manifests وإزالة موارد Docker ونتيجة `git status`. مجرد بدء أمر، أو عدم ظهور شيء في السجل، لا يُعد دليلاً على النجاح.
