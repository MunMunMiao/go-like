# Référence des paquets et fournisseurs

Cette page est organisée autour de la question que l'application cherche à résoudre, et non autour de l'arborescence `packages/`. Importez depuis le plus petit paquet public propriétaire du contrat. Le comportement propre au runtime est exposé par un sous-chemin explicite. Les paquets fournisseurs ne sont pas des implémentations interchangeables avec une garantie universelle unique.

## Lire cette page

- **Contrat** désigne une interface portable ou neutre vis-à-vis du fournisseur.
- **Fournisseur** désigne une implémentation adossée à la mémoire, à un fichier, à un service réseau ou à une bibliothèque native.
- **Adaptateur de cycle de vie** désigne un wrapper `Server` autour d'une ressource native créée par l'application.
- **Preuve** indique le type d'appui fourni par le dépôt : source/export, tests déclarés ou résultat d'une commande locale rapporté. Cela ne transforme pas une version de paquet en affirmation de publication npm ou de disponibilité en production.

L'inventaire source actuel contient 43 manifests de paquets `@go-like/*` non privés et 23 sous-chemins source publics, tous en version `0.0.1` dans ce checkout. Les 44 workspaces `examples/*` sont des applications privées, pas des paquets publics.

## Choisir selon le besoin

| Besoin                                   | Commencer avec                         | Ajouter si nécessaire                                                  | go-like ne possède pas                                               |
| ---------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Exposer une API Web                      | `@go-like/web`, `@go-like/core`          | `@go-like/web/node` ou le handler Fetch natif d'un framework            | Routeur, middleware du framework, auth, policy de réponse           |
| Appeler un service interne               | `@go-like/client`, `@go-like/transport`  | `@go-like/transport-memory`, `@go-like/transport-http`, `@go-like/struct` | Idempotence métier, IDL généré, RPC full-duplex                     |
| Découvrir des instances de service       | `@go-like/registry`                     | Un fournisseur Registry, des filtres, un Selector                      | Cohérence des leases/révisions du backend ou service locator global |
| Charger la configuration                 | `@go-like/config`                       | env/file/YAML ou un fournisseur Config externe                         | Configuration globale implicite et transactions inter-ressources    |
| Stocker des octets faisant autorité      | `@go-like/store`                        | Fournisseur Memory, File, Consul, etcd ou Vault                        | Base de données/ORM générique ou garanties uniformes du fournisseur |
| Mettre en cache des valeurs jetables     | `@go-like/cache`                        | Fournisseur Memory ou Redis                                            | Autorité, persistance, CAS, état métier durable                     |
| Publier ou consommer des octets          | `@go-like/broker`                       | Memory, RabbitMQ ou NATS                                               | ack/nack/term universels, DLQ, offset durable, exactly-once         |

| Exécuter un scheduler ou worker existant | `@go-like/core`                         | `@go-like/croner`, `@go-like/bullmq`, `@go-like/nats`                     | Queue, processor, policy de job ou connexion broker native          |

## Matrice de décision runtime

| Entrée ou famille de fournisseurs                               | Source portable                                | Natif Bun/Node                                    | Affirmation Deno                               | Formulation de preuve                                                                       |
| --------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Context, Core root, Health, Metadata, Resilience, Struct        | Oui                                            | Aucun import natif requis                         | Des lanes runtime sélectionnées sont déclarées | Contrat source ; vérifiez la matrice actuellement exécutée avant une formulation de release |
| Web root et Web health                                          | Oui                                            | Host requis séparément                            | Frontière Handler standard                     | Le Handler est portable ; un Handler n'est pas un listener                                  |
| Memory Transport, Memory Store, Memory Cache, Memory Broker     | Source locale au processus                     | Aucun service externe                             | Même sémantique locale au processus            | Ni distribué, ni durable, ni interprocessus                                                 |
| HTTP root et fournisseurs Config/Registry/Store adossés à Fetch | Fetch injecté                                  | Le runtime choisit Fetch                          | Source étayée là où la lane du paquet existe   | Portable par source ou lane déclarée, pas de parité universelle                             |
| Sous-chemins `/node`                                            | Non                                            | Spécifiques Node, avec exécution possible sur Bun | Aucun entrypoint Deno                          | Un import explicite modifie le graphe runtime                                               |
| NATS, RabbitMQ, BullMQ, Redis, Pino, Winston, SDK natifs OTel   | Dépend du fournisseur                          | Fixtures Node/Bun ou preuve propre au paquet      | Ne pas déduire le support Deno                 | Lisez le README du fournisseur et le périmètre E2E                                          |
| ZooKeeper                                                       | Pas de support Deno dans le README fournisseur | Node/Bun                                          | Explicitement non pris en charge               | Ne généralisez pas depuis la racine Registry                                                |

## Règles de sélection des fonctions

- Utilisez `contextHandler` à la frontière Web lorsque vous avez besoin d'un Context, plutôt qu'une sacoche de requête propre au framework.
- Utilisez `newApp` et `server(...)` lorsqu'un processus possède plusieurs ressources admises, ou lorsque la propriété du signal et de l'arrêt doit être explicite.
- Utilisez `endpoint(...)` typé et `handler(contract, fn)` lorsque les deux côtés doivent partager une validation Struct runtime. Utilisez `handler(service, endpoint, fn)` brut lorsque l'application possède un autre contrat d'octets.
- Utilisez `withAddress(...)` avant Discovery. C'est plus simple à tester et l'identité de la destination est explicite.
- Utilisez `withDiscovery(...)`, `withSelector(...)`, `withFilter(...)` et `withBlock()` uniquement si le service a besoin du comportement de plan de contrôle qu'ils ajoutent.
- Utilisez `withRetry(...)` seulement après avoir écrit l'autorisation de rejeu, le nombre maximal total de tentatives, le prédicat d'échec et l'idempotence métier.
- Utilisez `newMemoryStore` pour des tests déterministes, pas pour revendiquer une durabilité.
- Utilisez `newMemoryCache` pour une accélération jetable, pas comme autorité des rendez-vous ou des paiements.
- Utilisez `newBrokerServer` pour rattacher une souscription à Core, pas pour obtenir un worker de file universel ni une API de règlement.
- Utilisez `newOtelServer`, `newPinoServer`, `newWinstonServer` ou un Handler Prometheus seulement après que l'application a créé le fournisseur ou Registry natif.

## Exclusions explicites

Aucun paquet de l'inventaire public actuel ne doit être documenté comme prenant en charge gRPC, Protobuf, la génération de code IDL, des clients RPC générés, des streams internes full-duplex, un Event Store/historique/replay, une authentification/autorisation générique, un comportement ORM, un service locator global ou l'orchestration de clusters. Un fournisseur ou une application peut utiliser une bibliothèque distincte pour l'une de ces responsabilités, mais cela resterait en dehors du contrat go-like actuel.
